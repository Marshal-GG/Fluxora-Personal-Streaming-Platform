# Append an AGENT_LOG.md entry

You are appending a NEW entry to `f:/AI Models/Projects/Fluxora/AGENT_LOG.md` at the END of the file. The log is **append-only** — never edit past entries.

## Header

```
## [YYYY-MM-DD] [tag1] [tag2] [tag3] — Topic A · Topic B · Topic C

**Phase:** Phase N — short context line
**Status:** Complete | In progress | Blocked
**Commits:** <sha1>, <sha2>   ← or "uncommitted" while in flight
```

Today's date is in the system reminder's `# currentDate` block — use that, not training-data assumptions.

## Tags (small fixed vocabulary, comma-grep-friendly)

| Tag | When to use |
|---|---|
| `[mN]` | Mobile redesign milestone work (e.g. `[m11]`, `[m14]`) |
| `[fix]` | Bug fix |
| `[feat]` | New feature / capability |
| `[refactor]` | Code reshape with no behaviour change |
| `[docs]` | Documentation updates only or doc-heavy session |
| `[tests]` | New tests or test-infra work |
| `[audit]` | Audit / cross-check session that surfaces gaps |
| `[infra]` | Build, CI, distribution, packaging |
| `[server]` | Server-side work |
| `[mobile]` | Mobile-side work |
| `[desktop]` | Desktop-side work |
| `[core]` | `packages/fluxora_core` work |

Pick the smallest accurate set. Tags help future grep, not vanity.

## Body sections (in order; omit when empty)

```
### What Was Done                  ← always present
### Files Created / Modified       ← always present (3-column table)
### Docs Updated                   ← list every docs/ file touched
### Decisions Made                 ← only when there's a real judgement call
### Issues / Sharp Edges Discovered ← things the next agent should know
### Test Counts (re-baselined)     ← whenever tests changed
### Working-Tree Status            ← when uncommitted state matters for next agent
### Next Agent Should              ← always present
```

### `### Files Created / Modified` — exact shape

```
| Action | Path | Why |
|---|---|---|
| Created | apps/server/services/foo.py | Implements the new bar pipeline (§4.5) |
| Modified | apps/mobile/lib/.../baz.dart | Resource leak fix |
```

- Action: `Created` / `Modified` / `Deleted` / `Renamed` (exact words)
- Path: bare, no parenthetical
- Why: one short line, never paragraphs

### `### Test Counts (re-baselined)`

Only when tests changed. Show the delta:

```
- Server: **792 passing** (775 → 792, +17 across test_stream / test_settings / test_client_codec_service)
- Mobile: **78 passing** (unchanged)
- Desktop: **113 passing** (unchanged)
- Core: **8 passing** (untouched)
```

### `### Next Agent Should` — numbered, concrete

Each item names a specific file / endpoint / milestone. No "consider exploring…", no "verify everything looks good".

## Don't

- **Don't edit past entries.** Append-only.
- **Don't include AI branding** — no "Co-Authored-By: Claude", no "Generated by …" (CLAUDE.md Hard Prohibition #2).
- **Don't reference the log from commit messages** — commit messages describe code, not the log entry.
- **Don't paste diffs.** The Files table + Why is enough; readers can `git show`.
- **Don't write decision-paragraphs.** Decisions are 1–2 sentences each; longer reasoning belongs in a planning doc.
- **Don't recite Hard Rules** ("[x] No print()…") — performative; CLAUDE.md is already authoritative.

## Worked example

See `f:/AI Models/Projects/Fluxora/AGENT_LOG.md` — the latest entry is always the closest reference. Format spec at `docs/12_guidelines/04_agent_log_format.md` (only read if a question isn't answered by this skill).

## Log rotation

If `AGENT_LOG.md` exceeds ~1000 lines BEFORE you append, first archive it to `docs/logs/AGENT_LOG_archive_NN.md` (next available NN), write a fresh `AGENT_LOG.md` with a 5–10 line summary header pointing at the archive, then append your new entry to the fresh log.

## How to write

1. Read the LAST entry in `AGENT_LOG.md` for the line number to insert after.
2. Use `Edit` with the last paragraph of the previous entry as `old_string` and the same paragraph + `\n\n---\n\n## [date] [tags] — …\n\n…your new entry…` as `new_string`. This is the safest append shape.
3. Don't use `Bash` heredocs — backtick + single-quote combos in markdown break shell quoting.

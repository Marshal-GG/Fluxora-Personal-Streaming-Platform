## What's next

See `AGENT_LOG.md` "Next Agent Should" section for the prioritised list. As of 2026-05-09:

1. **Library-side AV1 / VP9 → H.264 sidecar transcode pipeline** — drafted in [`docs/10_planning/18_library_transcode_plan.md`](../10_planning/18_library_transcode_plan.md) on 2026-05-09; not yet built.  Pre-transcodes AV1 / VP9 sources to H.264 sidecars at scan time so playback can stream-copy instead of live-transcode.  Phase 5+ deliverable.
2. **iOS player polish** — PIP + lockscreen / Now Playing card. `media_kit` uses MPV which doesn't bridge to `AVPictureInPictureController`; implementing iOS PIP requires either swapping the player backend or a custom AVFoundation surface.  iOS lockscreen needs `UIBackgroundModes = audio` in `Info.plist` and a verification pass — `audio_service` already supports it, just couldn't be tested without an iOS device this round.
3. **HDR tonemap on the transcode path.** `hdr_format` is already stored from ffprobe at scan time. Add the `zscale` tonemap filter chain when the source is HDR and the active encoder isn't HDR-aware, so AV1 / VP9 HDR sources transcode to watchable SDR instead of washed-out/black output.
4. **Slice B — GPU hardware detection.** `/transcoding/devices` endpoint enumerating GPU models + per-codec NVDEC capability via `nvidia-smi -L` / `wmic` / `lspci`. Lets `_input_decoder_args` refuse upfront instead of failing at FFmpeg launch.
5. **Replace bundled FFmpeg with a libdav1d-enabled build.** The current bundled FFmpeg's software AV1 decoder fails on common HDR sources (`[av1] Failed to get pixel format`). Tracked as a manual task.
6. **Mobile app redesign — M13 + M14.** M10 / M11 / M12 all closed 2026-05-08.  M13 (host-a-server shell) is gated on the Phase 5+ phone-as-server runtime; M14 (polish + a11y + golden tests) is the redesign-completion pass.  Plan in `docs/11_design/mobile_redesign_plan.md` §7.
7. **Phase 6 routing hardening** — operator-driven Cloudflare config (Access policies, WAF rules, tunnel-health alerts, TURN evaluation).
8. **Dependabot triage** — Dart 3.9 floor bump may have unstuck PRs blocked on `json_annotation 4.11+`, `go_router 17.x`, `json_serializable 6.13+`.

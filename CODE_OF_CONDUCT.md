# Code of Conduct

> **Effective:** 2026-05-06
> **Maintainer:** Marshalx — portfolio at <https://marshalx.dev>, GitHub `@Marshal-GG`

Fluxora is a small open-source project. This document sets the baseline for how we work together — in issues, pull requests, GitHub Discussions, and any other Fluxora-owned space.

This Code applies to everyone who participates: maintainers, contributors, casual issue reporters, and anyone interacting with Fluxora's community spaces.

---

## The short version

**Be honest, specific, and kind.** Disagree about ideas, not about people. If something is unclear, ask. If you make a mistake, own it and fix it. If someone else makes one, prefer a direct correction over public escalation.

The rest of this document is what to do when the short version isn't enough.

---

## Standards we actually care about

These are the behaviours that make a small open-source project pleasant to work in. None of them are about tone-policing every comment — they're about substance.

### What helps

- **Specific issue reports.** Reproduction steps, version info, what you expected vs. what happened. A vague "it's broken" is much harder to act on than "Server 0.1.0 + Mobile build 142, after pairing succeeds the `/info` request times out — full server log attached."
- **Pull requests with context.** A short description of what changed and why. Linked issue if there is one. Tests if the change is testable.
- **Asking before changing.** If you're about to file a large refactor or rewrite, open a Discussion or draft PR first. We'd rather coordinate than reject a 3,000-line PR.
- **Patience.** This is a one-maintainer project. Response times are measured in days, not minutes.
- **Direct, honest disagreement.** "I think this approach is wrong because X" is welcome. "This is dumb" is not — same content, different signal.
- **Crediting prior work.** If you ported an idea from another project, say so in the PR description.

### What doesn't help

- **Personal attacks, harassment, or insults** in any form. Disagreements about code, design, or priority are not insults; calling someone names is.
- **Demands.** "Fix this now" / "When are you going to add X" / "This is unacceptable" — we get the urgency, but those framings don't speed anything up. A specific request with reasoning gets more traction.
- **Public shaming over private problems.** If a contributor breaks something, the first move is a direct correction, not a callout post. Maintainers are held to the same rule.
- **Off-topic content** in issues / discussions — no recruiting, no marketing, no political flame wars unrelated to the project.
- **AI-generated submissions without disclosure.** AI-assisted code is fine and common; passing off entire copy-pasted AI output as your own work without saying so isn't. We'd rather know.
- **Sealioning, JAQing off, repeated rules-lawyering.** If a maintainer tells you something is out of scope or won't be merged, the answer is "OK, fork it" — not 14 follow-up comments demanding justification.

### Things that get an immediate ban

These are non-negotiable. One strike is enough.

- Threats of violence — direct or implied — against any contributor.
- Doxxing — publishing or threatening to publish anyone's personal information.
- Sexual harassment of any kind, including unwanted advances and explicit content directed at someone who has not consented.
- Posting content that's illegal under Indian law where the maintainer operates (CSAM, etc.).
- Repeated, obvious bad-faith engagement — e.g. coming back under a new account after being banned.

## Reporting

If something happens that isn't OK, you can report it.

**Channels** (in order of preference):

1. **Email** — `conduct@fluxora.marshalx.dev` (preferred) or `marshalgcom@gmail.com` (fallback). One person reads these — Marshalx, the maintainer.
2. **GitHub** — direct message via `@Marshal-GG`.
3. **Private security advisory** — only if the conduct issue is mixed up with a security report (e.g. someone is harassing you and threatening to leak credentials). Use <https://github.com/Marshal-GG/Fluxora-Personal-Streaming-Platform/security/advisories/new>.

When you report, include:

- What happened (links to comments / issues / PRs if applicable).
- Who's involved.
- What you'd like to happen (warning / ban / mediation / nothing — just a record).
- Whether you're OK with the maintainer naming you to the other party. By default we keep reporter identity confidential.

**You will not be retaliated against for reporting in good faith.** Even if the report turns out to be a misunderstanding, the act of reporting is welcome. We'd rather have one false alarm than miss a real problem.

### Response

| What | Within |
|------|--------|
| Acknowledge receipt | 72 hours |
| Initial assessment + first response to you | 7 days |
| Resolution | Varies — could be a private conversation, a public clarification, a temporary ban, or a permanent ban. |

The maintainer makes the final call. If you disagree with the decision, you can escalate by publishing your own write-up — we won't censor you on platforms we don't own — but the in-project decision stands.

## Enforcement responsibilities

The maintainer is responsible for:

- Clarifying these standards when they're vague.
- Acting on reports.
- Enforcing the rules consistently regardless of who's involved (including past maintainers, top contributors, sponsors, etc.).

The maintainer is **not** responsible for:

- Adjudicating off-Fluxora behaviour. We can't control what someone says on Twitter or in a private Discord. If their off-Fluxora behaviour rises to the level of being a credible threat to Fluxora contributors, we'll act on it; otherwise, take it up there.
- Refereeing technical disagreements that aren't conduct issues. "I think your design is wrong" is a code review, not a Code of Conduct report.

---

## Enforcement guidelines

The maintainer will follow this rough escalation ladder, adjusted for severity:

1. **Private clarification.** "Hey, that comment came across as X — did you mean Y?" Most issues resolve here.
2. **Public correction.** A maintainer comment in the relevant thread saying "this isn't OK, please rephrase / step back."
3. **Temporary ban from project spaces** (issues, PRs, discussions) — typically 1-4 weeks.
4. **Permanent ban.**

Severe behaviour (the immediate-ban list above) skips straight to step 4.

---

## Scope

This Code applies to:

- The Fluxora GitHub repository — issues, PRs, code, comments, reviews.
- Fluxora GitHub Discussions.
- Any future official Fluxora community space (Discord, Matrix, etc.) when those exist.
- Public statements made as a representative of the project (e.g. tweets posted from a `@Fluxora` account, blog posts on `fluxora.marshalx.dev`, etc.).

It does not apply to:

- Personal Twitter accounts, blogs, or off-platform communication unless those interactions cross over into Fluxora-owned spaces.
- Forks of the Fluxora codebase. Forks are governed by their own maintainers.
